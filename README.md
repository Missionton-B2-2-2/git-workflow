## GitHub Flow 선택 이유
- 단순한 브랜치 구조: `main`과 `feature` 브랜치를 중심으로 작업하여 브랜치 관리가 간결해짐
- PR 기반 협업: 작업별 브랜치에서 독립적으로 작업하고 리뷰를 거쳐 병합하므로 변경 사항을 검증할 수 있습니다.
- 안정적인 `main` 유지: 승인된 변경 사항만 병합하여 `main` 브랜치를 안정적인 상태로 유지할 수 있습니다.
