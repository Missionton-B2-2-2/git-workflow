# Git stash 학습 노트

## 작성자

- greenable-7

## 학습 목적

완성되지 않은 작업을 커밋하지 않고 잠시 보관한 뒤, 다른 브랜치로 이동하고 작업을 다시 복원하는 방법을 학습한다.

## 핵심 개념

- `git stash`: 커밋하지 않은 변경 사항을 임시로 보관한다.
- `git stash list`: 보관된 작업 목록을 확인한다.
- `git stash pop`: 보관한 작업을 복원하고 stash 목록에서 제거한다.
- `git stash apply`: 보관한 작업을 복원하지만 stash 목록에는 유지한다.

## 실습 과정

1. `stash-demo.txt`에 커밋하지 않은 변경을 만들었다.
2. `git stash push`로 변경 내용을 임시 보관했다.
3. 작업 폴더가 깨끗해진 것을 확인하고 `main` 브랜치로 이동했다.
4. 원래 작업 브랜치로 돌아왔다.
5. `git stash pop`으로 변경 내용을 복원했다.
6. stash 목록이 비어 있는 것을 확인했다.

## 실습 결과

작업 내용을 잃지 않고 다른 브랜치로 이동할 수 있었다. 원래 브랜치에서 `git stash pop`을 실행하자 수정 내용이 정상적으로 복원됐다.

## 사용하면 좋은 상황

긴급한 수정 요청으로 다른 브랜치에 이동해야 하지만, 현재 작업이 아직 커밋할 정도로 완성되지 않았을 때 사용한다.

## 주의점

stash를 복원할 때 현재 브랜치의 변경과 겹치면 충돌이 발생할 수 있다. 복원 후에는 `git status`와 `git diff`로 작업 상태를 확인해야 한다.
